# Web2SSH - Beginner CTFd Whale Challenge

## 📌 Overview

**Web2SSH** is a beginner-level CTF challenge engineered specifically to demonstrate and validate key features of **CTFd Whale** (dynamic container management plugin for CTFd):

1. **Per-user Isolated Containers:** Each player gets their own standalone container instance.
2. **Per-user Dynamic Flag Injection:** Unique flags injected at runtime via environment variables (`FLAG`).
3. **Multi-Service Exposure:** A single container hosting both an **HTTP Web Service (8080)** and an **SSH Service (22)**.
4. **Automated Lifecycle Management:** Automatic spawning, port routing, and destruction of containers by CTFd Whale.

[ Player ]

## 🏗️ Architecture & Per-User Isolation

```
                   ┌─────────────────────────────────────────┐
                   │               CTFd Whale                │
                   └──────────────────┬──────────────────────┘
                                      │
           ┌──────────────────────────┴──────────────────────────┐
           │ Spawns isolated containers & injects $FLAG          │
           ▼                                                     ▼
┌───────────────────────────────┐                     ┌───────────────────────────────┐
│ Player A Container            │                     │ Player B Container            │
│  - Web Service (0.0.0.0:8080) │                     │  - Web Service (0.0.0.0:8080) │
│  - SSH Service (0.0.0.0:22)   │                     │  - SSH Service (0.0.0.0:22)   │
│  - FLAG=CTF{player_a_secret}  │                     │  - FLAG=CTF{player_b_secret}  │
│  - /home/ctf/flag.txt (0400)  │                     │  - /home/ctf/flag.txt (0400)  │
└───────────────────────────────┘                     └───────────────────────────────┘
```

### Key Implementation Details:
* **No Baked-in Flag:** The Docker image contains NO static flags. Flags are generated by CTFd Whale and passed via environment variable `FLAG` at container creation.
* **Startup Script (`entrypoint.sh`):** Upon container launch, `entrypoint.sh` reads `$FLAG`, writes it into `/home/ctf/flag.txt`, sets file permissions to `0400` owned by `ctf:ctf`, unsets `$FLAG` from process memory, and boots SSH & Flask.
* **Non-Root SSH User:** The user connects as non-root user `ctf`.
* **Multi-Port Forwarding:** `Dockerfile` explicitly specifies `EXPOSE 8080` and `EXPOSE 22`.

## 🐳 CTFd Whale Deployment & Configuration

### 1. Requirements
* CTFd instance with **CTFd-Whale** plugin installed.
* Docker daemon accessible by CTFd Whale.
* `ctfcli` (optional, for deploying via CLI).

### 2. Whale Environment Variable & Configuration (`challenge.yml`)

```yaml
name: "Web2SSH"
author: "Antigravity"
category: "Web"
value: 500
type: dynamic_docker

extra:
  initial: 500
  decay: 100
  minimum: 50
  docker_image: web2ssh-challenge:latest
  redirect_type: http
  redirect_port: 8080
```

#### How CTFd Whale Displays Dual-Exposed Ports:
1. **Web Service (`redirect_type: http`):**
   - CTFd Whale generates a **Link to Challenge / Website Link** button in the player's Instance Info panel (e.g., `http://<lan_domain>:<web_port>`).
2. **SSH Service (Port 22):**
   - Port 22 is allocated a dynamic host port by CTFd Whale. The mapped SSH host and port are displayed under **Instance Info** or accessed via `ssh ctf@<domain_or_ip> -p <mapped_ssh_port>`.

### 3. Flag Injection Mechanism in CTFd Whale
Whale passes the container-specific flag as an environment variable when running `docker run`:

```bash
docker run -d \
  -e FLAG="CTF{unique_per_user_random_hash}" \
  -p <host_web_port>:8080 \
  -p <host_ssh_port>:22 \
  web2ssh-challenge:latest
```

## 🧪 Local Testing & Verification

### Option A: Testing Multi-User Isolation with Docker Compose

Run two separate simulated player instances locally:

```bash
cd web2ssh
docker-compose up --build -d
```

This starts:
- **Player A Container (`web2ssh_player_a`):**
  - Web: `http://127.0.0.1:8081`
  - SSH: `ssh ctf@127.0.0.1 -p 2221` (Password: `web2ssh_access_2026`)
  - Injected Flag: `CTF{user_a_per_user_isolated_flag_11111}`

- **Player B Container (`web2ssh_player_b`):**
  - Web: `http://127.0.0.1:8082`
  - SSH: `ssh ctf@127.0.0.1 -p 2222` (Password: `web2ssh_access_2026`)
  - Injected Flag: `CTF{user_b_per_user_isolated_flag_99999}`

#### Solve Player A:
```bash
python3 solution/solve.py 127.0.0.1 8081 127.0.0.1 2221
```

#### Solve Player B:
```bash
python3 solution/solve.py 127.0.0.1 8082 127.0.0.1 2222
```

Notice that Player A and Player B receive distinct flags!
